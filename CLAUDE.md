## Architecture

### Routing
`src/App.tsx` is the root. Pages in `src/pages/` are **lazy-loaded** via
`React.lazy` + `Suspense`, wrapped in Framer Motion's `AnimatePresence`.
Routes: `/`, `/about`, `/projects`, `/projects/:slug`, `/hobbies`, `/writings`,
`/certifications`, `/career-artifacts`, `/contact`, `/resume`, `/presentation`,
plus a `*` 404. SPA fallback is handled by `vercel.json` rewrites.

Provider order in `App.tsx`: `ThemeProvider` → `ErrorBoundary` →
`HelmetProvider` → `BrowserRouter`.

### Data flow — READ THIS BEFORE EDITING CONTENT

**`src/data/profile.ts` (~1300 lines) is the single source of truth for almost
everything on the live site. Edit it by hand.**

It is imported by 12 modules: `pages/Home`, `About`, `Projects`,
`ProjectDetail`, `Resume`, `Writings`, `components/Header`, `Footer`,
`StructuredData`, `VolunteeringExperience`, `WritingsSection`, and
`utils/search.ts`.

- **Never run `npm run build:profile`** (`scripts/generate-data.mjs`). Its
  `// Auto-generated by scripts/generate-data.mjs` header at the top of
  `profile.ts` is misleading — the generator is **stale** and regenerates a
  much thinner file from `content/`, destroying hand-authored data
  (the `Volunteering` interface/section, the "Off-Campus Ambassador" role,
  the "Academic Focus" skill group, the long markdown-formatted experience
  bullets). Treat `generate-data.mjs`, `build-profile.mjs` and
  `npm run build:profile` as **deprecated**.

Other hand-maintained data in `src/data/`: `certificates.ts`, `skills.ts`,
`hobbies.ts`, `testimonials.ts`, `documents.ts`, `technicalTerms.ts`,
`newsletter.json`.

#### What is actually dead (verified by grep, 2026-09-16)
- `src/data/timeline.ts` — **no importers**. `About.tsx` instead defines
  `professionalStatus`, `currentWork` and `technicalEvolution` as inline consts
  (lines ~39-72) and renders the timeline with
  `react-vertical-timeline-component`.
- `content/experience/*.md` — referenced **only** by the stale generator;
  never rendered. Experience comes from `profile.ts`.
- `content/writing/*.md` — **not rendered**. The Writings page reads
  `profile.ts` + `src/data/newsletter.json`. `loadWriting()` in
  `src/utils/content.ts` is an unused export.
- `content/projects/*.md` — only a **fallback**. `ProjectDetail.tsx` first
  looks up `profile.projects` by `id === slug`; it calls `loadProjects()`
  only if that misses. Since every live project is in `profile.ts`, the
  markdown path is effectively dormant.
- `content/profile.json` — generator input only.

So: `src/utils/content.ts` is imported by exactly one file
(`ProjectDetail.tsx`), and mainly for its `processMarkdown()` helper, which
renders the markdown stored *inside* `profile.ts` bullets/content through
`unified` → `remark-parse` → `remark-gfm` → `remark-rehype` → `rehype-slug`
→ `rehype-stringify`.

**Practical rule: to change site content, edit `src/data/*.ts` — not
`content/`.** Ask before deleting anything under `content/`; the `.pptx`,
resume PDF and markdown there are still archival source material.

## Media / assets
Everything is served from `public/` at the site root. Formats matter here:
project heroes and hobby photos are **WebP**, hobby videos are **H.264 MP4**
with faststart. Do not add PNG/JPEG heroes or `.MOV`/HEIC files back:

- The originals were 800KB-1MB PNGs (13MB total) and VP9-in-MOV videos that
  Safari could not play. They were converted in Sept 2026.
- HEIC does not render in Chrome or Firefox at all.
- `public/` is the deploy payload. It was 462MB and is now ~214MB; the deploy
  step stalled for hours at the larger size.

Current layout: `public/projects/` (17 WebP heroes named `<project-id>.webp`),
`public/hobbies/` (16 WebP + 12 MP4), `public/documents/`, `public/certificates/`,
`public/vdrs-presentation/`, `public/hero-motocorp/`.

Image paths live in the `images` arrays in `src/data/profile.ts` (projects) and
`src/data/hobbies.ts` (hobbies). **Anything in `public/` that nothing
references is dead weight shipped on every deploy** - 112 such files were
removed in Sept 2026. Check references before adding assets.

⚠️ **`MEDIA_GUIDE.md` is out of date** - it documents the old
`/internship/DSC01xxx.JPG` mapping and PNG paths. Trust the data files.

## Deployment / CI
`.github/workflows/pipeline.yml`, on push to `main`/`develop` and PRs to `main`:
1. **verify** - `npm run lint`, `npx tsc --noEmit`,
   `npm audit --audit-level=high --omit=dev`, `npm test`
2. **build** - `npm run build`, uploads the `dist/` artifact
3. **deploy** - push to `main` only:
   `npm i -g vercel@latest`, then `vercel pull` / `vercel build --prod` /
   `vercel deploy --prebuilt --prod --archive=tgz`, using the
   `VERCEL_TOKEN` / `VERCEL_ORG_ID` / `VERCEL_PROJECT_ID` secrets.

**Do not reintroduce `amondnet/vercel-action`.** It pinned Vercel CLI 25.1.0
and the deploy endpoint now requires >= 47.2.2, so it fails outright. The
Vercel project is `ajiths-projects-12e1832d/portfoliovone`.

`--archive=tgz` is there because the deploy step once stalled 3.4 hours
uploading a 462MB payload. If it stalls again, the durable fix is Vercel's
Git integration (Vercel clones the repo itself, no runner upload).

`vercel.json` adds the SPA rewrite and security headers. Vercel matches the
filesystem **before** the rewrite, which is what makes prerendered routes work.

`dist/` is gitignored and untracked.

## Prerendering (`scripts/prerender.mjs`)
Runs automatically after `vite build`. The app is a client-rendered SPA, so
without this every route serves the same `index.html` with an empty `#root`
and non-JS crawlers (GPTBot, ClaudeBot, PerplexityBot) see nothing.

It writes one HTML file per route (34: 9 static pages + 25 project pages) with
that route's title, description, canonical, Open Graph tags, JSON-LD and the
page's content in `<noscript>`. It also **regenerates `public/`-equivalent
`dist/sitemap.xml`** from the same route list, so the sitemap cannot drift.

It reads content out of `src/data/profile.ts` by brace-matching the JSON
arrays. If you restructure `profile.ts` heavily, check this still parses.

**It is not full DOM prerendering.** Every page is `React.lazy`, so a real SSR
pass would emit the Suspense fallback instead of the page. Doing it properly
means reworking the lazy boundaries.

## Environment variables
All client vars are **`VITE_`-prefixed** (see `env.example`): `VITE_SITE_URL`,
`VITE_SITE_NAME`, `VITE_FORMSPREE_ENDPOINT`, `VITE_CONTACT_EMAIL`,
`VITE_GA_ID`, and the social URLs. `.env*` is gitignored. There are no
server-side secrets in the app — it is fully static.

## Testing
`src/App.test.tsx` is a single **smoke test** only (renders a div and asserts
text). `src/test/setup.ts` mocks `window.matchMedia` for the theme code. There
is no real component coverage — don't assume a change is safe because the
tests pass; check the page in `npm run dev`.

⚠️ **`npm test` currently does not run on this machine** (verified 2026-09-16).
Vitest never boots its worker:

```
Error: [vitest-pool]: Failed to start threads worker for test files .../src/App.test.tsx
Caused by: Error: [vitest-pool-runner]: Timeout waiting for worker to respond
 Test Files  no tests
```

It fails the same way on both pools (`--pool=forks` hung 854s, `--pool=threads`
failed in 60s), so it is the worker startup, not the test. Zero tests are
collected — a "clean" local run here means **nothing ran**, not that it passed.
Two untested suspects: local **Node 26.8.2** vs Vitest 4.1.3 (CI uses Node 20
and passes), or OneDrive stalling the worker's `node_modules` reads. There is
no node version manager installed. **Rely on CI for test results**, and don't
report local tests as passing.

## Conventions / gotchas
- Functional components + Tailwind semantic classes + Framer Motion, matching
  the surrounding file. New atoms go in `src/components/ui/`.
- Edit `src/data/profile.ts` directly; never run `build:profile`.
- Before committing run `npm run lint` and `npx tsc --noEmit` — CI blocks on both.
- ESLint runs with `--max-warnings 50`; keep new warnings at zero rather than
  eating into that budget.
- The working tree often carries **uncommitted hand edits to `profile.ts` /
  `hobbies.ts`** (content updates in progress). Check `git status` and ask
  before stashing, resetting, or rebasing anything.
- Don't touch `src/internship/vdrspresentation-ref/` or `dist/`.
